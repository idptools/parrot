# PARROT2: in development

> **PARROT2 (version 2.0.0.dev0) is in active development on the `parrot2` branch and has not yet been released.** `pip install idptools-parrot` installs the latest release, PARROT 1.7.6 (May 2025), and the [online documentation](https://idptools-parrot.readthedocs.io/en/latest/) describes PARROT 1.7. To use PARROT2, install it from this branch (see below). Commands, options, and file formats may still change before it is released.

**PARROT** trains machine-learning models that map protein sequences to values, behind an easy-to-use command-line interface. PARROT is well-suited for a variety of protein bioinformatics tasks. With only an input data file containing sequences and their values, you can train, optimize, and test a network for whatever purpose, then apply it to new, unlabeled sequences to generate predictions and biological hypotheses.

PARROT handles regression and classification problems, with one value per sequence (sequence-mapped data), one per residue (residue-mapped data) or a matrix per sequence (matrix data, e.g. a contact map). The networks can be bidirectional recurrent neural networks (BRNNs, PARROT's original architecture), convolutional networks, U-Nets or transformers, and baselines built on sequence composition (a composition network and simple scikit-learn models) show how much a network gains from residue order. Sequences can be encoded with one-hot vectors, biophysical scales, your own table, protein language model embeddings or NARDINI+ features.

## What's new in PARROT2

PARROT2 is a substantial rewrite of PARROT 1. In brief:

* **Architectures:** `parrot-train` and `parrot-optimize` take the architecture as a subcommand: `brnn`, `cnn`, `unet`, `transformer`, and `composition`; the simple models `linear`, `svm`, `random_forest`, `knn`, and `gbrt`; and `unet2d` for matrix data. You can add new architectures as a single module.
* **Data:** matrix data, missing residue labels (NaN), regression values with uncertainties (`--uncertainties`, which weights each value by its measurement error), and parrot-preprocess, which cleans and deduplicates a data file, splits it into training, validation, and test sets without leakage between them (keeping similar sequences, found with MMseqs2 or PARROT's own k-mer search, in the same set), and balances classes.
* **Encodings:** protein language model embeddings (ESM-2 and ESM-C) and NARDINI+ features, computed once and cached, and standardized encodings.
* **Hyperparameter search:** `parrot-optimize` was rewritten without GPy/GPyOpt, combining successive halving with model-based sampling (TPE); with its defaults it costs about 15-20 times less than before.
* **Training:** Apple-silicon GPUs as well as NVIDIA ones (`--device`, and `--gpu-id` to choose among several NVIDIA GPUs), giving the same predictions on every device to about 1e-4, batching by sequence length, masked padding (a network's output depends on how sequences are batched only through float32 rounding), reproducible runs with `--seed`, and a `<network>_info.txt` describing how each network was trained, in enough detail for a paper's methods section.
* **Saved networks** record their architecture, hyperparameters, task, and encoding, so `parrot-predict` and `Predictor` need nothing else. Networks saved by PARROT 1 still load and predict as before, up to float32 rounding (as they recorded only their weights, they still need their datatype: `-d` for `parrot-predict`, with `--encode` if it was not one-hot, and `dtype` for `Predictor`).
* **Command line:** every input is named (`--input-file`, `--output-network`, `--regression` or `--classification --num-classes N`), and `--split` is required. Commands in PARROT 1 form stop with a message telling you what to use instead.
* **Requirements:** Python 3.11 or newer, NumPy 2.3 or newer, and PyTorch 2.8 or newer.

The change log at the end of this page lists every change.

## Installation:

PARROT2 is installed from the `parrot2` branch on GitHub:

	$ pip install "git+https://github.com/idptools/parrot.git@parrot2"

It is possible that you may experience errors depending on what Python packages are already installed on your machine. If you encounter this, try installing PARROT in a "clean" virtual environment using conda:

	$ conda create --name <env_name> python=3.11
	$ conda activate <env_name>

Then install PARROT with pip.

Alternatively, to clone the GitHub repository and gain the ability to modify a local copy of the code, run:

	$ git clone https://github.com/idptools/parrot.git
	$ cd parrot
	$ git checkout parrot2
	$ pip install -e .

This installs PARROT in editable mode, so changes you make to the source code take effect without reinstalling.

**Optional extras:** protein language model encodings need the `plm` extra (ESM-2) or the `esmc` extra (ESM C), and NARDINI+ features need SPARROW (`pip install git+https://github.com/idptools/sparrow.git`). From a clone, install an extra with `pip install -e ".[plm]"`; directly from GitHub, use `pip install "idptools-parrot[plm] @ git+https://github.com/idptools/parrot.git@parrot2"`. (`pip install idptools-parrot[plm]` would install PARROT 1.7.5 from PyPI.) `--split homology` (`parrot-preprocess`) and `--split mmseqs` (`parrot-train` and `parrot-optimize`) need MMseqs2, installed separately (e.g. `conda install -c conda-forge -c bioconda mmseqs2`).

**Hyperparameter search:** `parrot-optimize` needs no extra packages. (Earlier versions needed GPy and GPyOpt, installed with `pip install idptools-parrot[optimize]`; that command still works, but installs nothing extra.)

## Usage:

The documentation for PARROT2 is in the `docs` folder of this branch, with detailed information on installation and examples; `docs/README.md` explains how to build it. The [online documentation](https://idptools-parrot.readthedocs.io/en/latest/) describes PARROT 1.7.

Every command also explains itself: `-h` lists its options, and `--show-examples` prints a guide with worked examples of how to use it, what it does, and how it works (e.g., `parrot-train --show-examples`).

There are three primary commands that can be run within the parrot package:

1. Train a network with user-specified hyperparameters
2. Train a network with automatically-determined, optimal hyperparameters
3. Generate predictions on unlabeled sequences using a trained network

Two more commands help prepare data for them: `parrot-preprocess` cleans a data file and splits it into training, validation, and test sets, and parrot-cvsplit writes split files for k-fold cross-validation.

### Input data format:

Before data can be integrated into training a PARROT network, it must be formatted in the following manner:

	seqID1 seq1 seq1data1 <seq1data2> <seq1data3> ... <seq1dataN1>  
	seqID2 seq2 seq2data1 <seq2data2> <seq2data3> ... <seq2dataN2>  
	.
	.
	.  
	seqIDM seqM seqMdata1 <seqMdata2> <seqMdata3> ... <seqMdataNM>

Where Ni is the length of sequence i, and M is the total number of labeled sequences. Items must be whitespace-separated. For **sequence-mapped data** (i.e. each sequence constitutes a *single datapoint*), each row will only contain three columns.

Note that it is not required that sequences are the same length. For example, if Sequence #1 has 12 amino acids and Sequence #2 has 15 amino acids, these two rows in the input file will contain 14 and 17 fields, respectively.

Optionally, you may use datasets that exclude the first column containing the ID of each sequence. In this case, be sure to use the `--exclude-seq-id` flag. Blank lines and lines starting with `#` are ignored.

**Classification problem:** the labeled data should be integer class labels. For example, if there are 3 classes, then each datapoint should be either a '0', '1', or '2' (with no quotation marks).

**Regression problem:** If the user wishes to map each sequence or residue to a continuous real number, then each datapoint should be a float

**Missing residue labels:** for residue-mapped data, a residue with no label (e.g. a residue with no experimental measurement) can be written as `nan`. PARROT ignores these residues in training, in performance metrics and in figures, and writes `nan` for their true value in prediction output. Every sequence needs at least one labelled residue, and sequence-mapped data cannot contain missing values.

**Values with uncertainties:** for regression, each value can come with the standard deviation (SD) of its measurement error, written as `value,SD` (e.g. `3.21,0.15`; a missing residue value is still `nan`), with `--uncertainties`. Training then weights each value by 1/(SD² + s²), where s, the model error, is the error of the network's predictions beyond the values' own errors, fitted on the validation set. s is reported, and the test statistics say how well this account of the errors fits (the reduced chi-squared, the fraction of values within 1 and 2 total SDs, √(SD² + s²), of their prediction, and the noise ceiling). For the mean of n replicates, give the standard error, SD/√n. Every architecture supports it except `knn` and `unet2d`. See the "Values with uncertainties" documentation page.

**Matrix data:** PARROT can also learn a matrix of values per sequence, with one row per residue: a map of every pair of residues (L x L), or N related values per residue (L x N). The datafile then holds `<ID> <sequence>` on each line, and the matrices are in a NumPy `.npz` file, one array per sequence ID (`parrot-train unet2d --input-file data.tsv --output-network network.pt --split kmer --regression --matrix-file matrices.npz`). See the "Matrix data" documentation page.

For example datasets, see the TSV files provided in the **/data** folder.

### Preparing data: ``parrot-preprocess``

``parrot-preprocess`` turns a PARROT datafile into one ready for training. It can clean sequences, recode class labels, merge or remove duplicate sequences, and split the data into training, validation and test sets. ``--split homology`` uses MMseqs2 (installed separately, e.g. `conda install -c conda-forge -c bioconda mmseqs2`) with stringent criteria: any alignment with E <= 1e-3 covering at least 30% of the shorter sequence, at any identity. It keeps homologous sequences in the same set, then re-searches each set against the others until none shares a homologue with another. Without MMseqs2, ``--split kmer`` follows the same protocol with PARROT's own k-mer search: it needs nothing extra and removes leakage between close relatives (in the yeast proteome, all test-training pairs at >= 90% identity and nearly all at 50-90%), but not between distant homologues. It can also balance the classes of the training set. It writes the processed datafile, a split-file to train on with `parrot-train --split`, and a report:

```
parrot-preprocess data.tsv clean.tsv -d sequence -m classification --deduplicate merge --split homology --class-balance --seed 1
parrot-train brnn --input-file clean.tsv --output-network network.pt -d sequence --classification --num-classes 3 --split clean_split_file.txt
```

### 1. Train a network with provided hyperparameters: ``parrot-train``

The ``parrot-train`` command is the primary command for training a network with PARROT. Users choose a network architecture, then need only to specify their data, where they want to save their output, and some basic information on the type of machine learning problem they are tackling:

```
parrot-train brnn --input-file data.tsv --output-network network.pt --split kmer -d sequence --regression
```

Each architecture (`brnn`, `cnn`, `unet`, `transformer`, `composition`, the simple models `linear`, `svm`, `random_forest`, `knn` and `gbrt`, and `unet2d` for matrix data) is a subcommand with only the options that apply to it: `parrot-train -h` lists them, and `parrot-train cnn -h` shows the options of one. Every input is named: `--input-file` for the datafile, `--output-network` for the network (`.pt` is added if needed), and `--regression` or `--classification --num-classes N` for the task. Next to the network, `<network>_info.txt` records how it was trained, for reproducing it or for a paper's methods. Beyond this, there are a suite of other options that users can provide to tailor their network to their particular needs. Users can provide specific hyperparameters to craft their network, they can manually specify what samples in their data set are trained on and which are held out as test data, they can choose to output information and figures on their network's performance on the test data, and much more!

Neural networks also offer opt-in learning-rate schedules (`cosine`, `exponential`, or validation-driven `plateau`), linear warmup, gradient clipping and finite checks, and bounded recovery that replays a failed epoch at a lower rate. Residue and matrix tasks can optionally weight proteins equally by averaging each protein's labelled losses. Defaults retain a fixed user-specified learning rate and summed labelled losses, with clipping and recovery off. See [Training controls](docs/usage/training_controls.rst) for choosing settings, examples, and the optional training-history and recovery records.

For long runs, `--checkpoint` saves atomic resumable state and `--training-log` flushes epoch records as training proceeds. Continue with `parrot-train --resume <checkpoint>` or `parrot-optimize --resume <checkpoint>`, including partial searches and final CV retraining. Neural regression can select `--regression-loss mae|mse|huber`, with `--huber-delta` for Huber, and opt in to `--optimizer adamw --weight-decay <value>`. Defaults keep the original losses and Adam without weight decay. Optional `--amp` enables guarded CUDA mixed precision on supported GPUs; FP32 remains the default. See [Training controls](docs/usage/training_controls.rst) for resume constraints and hardware requirements.

Test reports now include MAE, RMSE, signed bias and R2, with mean protein errors for residue/matrix tasks. Per-protein and length-stratified metric tables accompany the pooled test statistics; `--no-stats` suppresses all three statistics files.

### 2. Optimize hyperparameters and train a network: ``parrot-optimize``

The ``parrot-optimize`` command searches for the best-performing hyperparameters of an architecture on a given dataset (e.g. ``parrot-optimize cnn --input-file data.tsv --output-network network.pt --split kmer -d residues --regression``), then trains and tests a network with them, as ``parrot-train`` would. It tunes the initial learning rate (for networks trained epoch by epoch; any chosen schedule, safeguards and recovery policy are fixed throughout the search) and every hyperparameter the architecture marks as searched (for the BRNN, the number of layers and the hidden vector size), dropping poor configurations after a few epochs (successive halving) and proposing new ones where good results have clustered (TPE). Any hyperparameter given on the command line is fixed rather than searched. It takes considerably longer than ``parrot-train``: the default 50 trials cost about as much as 15-20 training runs.

### 3. Generate predictions with a trained network: ``parrot-predict``

Once a network has been trained for a particular machine learning task, the user can generate predictions on new sequences with this network using the ``parrot-predict`` command. The user provides a list of sequences they would like to predict (`<ID> <sequence>` on each line) and the saved network, and a file is outputted with the predictions. The network file records its architecture, task and encoding, so no other options are needed (except, for a network trained with `--embedding-context`, the full-length proteins the sequences were cut from):

```
parrot-predict sequences.txt network.pt predictions.txt
```

In Python, `Predictor` does the same, for one sequence at a time or for a list of them:

```python
from parrot import Predictor

predictor = Predictor('network.pt')
values = predictor.predict('MKVLAAGIVGLLLA')
all_values = predictor.predict_batch(['MKVLAAGIVGLLLA', 'MSDNEEGQSKRRQ'])
```

`predict_batch` predicts the sequences together as `parrot-predict` does, which for more than a handful of sequences is much faster than `predict` on each: every sequence is encoded first (a protein language model runs over many sequences at once), then the network runs over batches of similar length. Its predictions match those of `predict` up to float32 rounding, not exactly, since which sequences share a batch changes the order of the floating-point operations (for a network trained on protein language model embeddings, the model also runs in batches, and a stored 16-bit embedding value can move by one step, so the predictions can differ by more).

### Cross-validation: ``parrot-cvsplit``

``parrot-cvsplit data.tsv cv/splits -k 10`` writes one split-file per fold (`cv/splits_cv0.txt` to `cv/splits_cv9.txt`), each with a different tenth of the data as its test set, to train a network on each fold with `parrot-train --split`. Identical sequences are kept in the same set, but close relatives are not; to score hyperparameters by cross-validation, use `parrot-optimize --cv-folds`.

### GPUs (CUDA and Apple silicon)

Every command that trains, predicts or embeds sequences takes `--device`, which is `auto` by default. This uses an NVIDIA GPU (CUDA) if one is available, otherwise an Apple-silicon GPU (MPS) if available, otherwise the CPU. Use `--device cpu`, `--device cuda` or `--device mps` to choose explicitly; asking for a device that is not available is an error. On a machine with more than one NVIDIA GPU, `--gpu-id N` chooses which one (numbered from 0). Trained networks are always saved with CPU tensors, so a network trained on any device can be loaded anywhere, and PARROT defaults to full float32 precision on every device (on NVIDIA GPUs it turns off TF32 while it runs), so a network gives the same predictions on any device to about 1e-4 or better. Opt-in `--amp` uses reduced precision for the CUDA training forward pass; evaluation and prediction remain FP32. In Python, `Predictor` also runs on a GPU if there is one; `Predictor(path, device='cpu')` uses the CPU anyway (which can be faster for a few sequences at a time, and is needed inside forked worker processes, where MPS cannot be used), and `Predictor(path, gpu_id=1)` the second NVIDIA GPU, as `--gpu-id 1` does.

### Encodings

Sequences are encoded with one-hot vectors by default. `--encode biophysics` uses nine biophysical scales instead, and `--encode <file>` uses your own table (see `data/encoding_example.txt`). `--standardize-encoding` rescales every feature of the encoding to mean 0 and standard deviation 1 across the amino acids, so that features measured on very different scales (e.g. molecular weight and an aromatic flag) contribute equally; it is recommended for `biophysics` and most user encodings. The standardization is saved with the network and applied automatically when predicting. See the `parrot-train` documentation for exactly what is done.

`--encode esm2_t12_35M_UR50D` (or another ESM-2 model, which needs the `plm` extra) or `--encode esmc_300m` / `esmc_600m` (EvolutionaryScale's ESM C, which needs the `esmc` extra; see Installation) encodes each residue by its embedding from a protein language model. Embedding is by far the slowest step, so `parrot-train` (and `parrot-optimize`) and `parrot-predict` embed each sequence once and store the embeddings in a cache directory next to their output (`parrot_train_embeddings` or `parrot_predict_embeddings`, each with a README), after printing how large the cache will be; `--embedding-cache` lets several runs share one cache, and `parrot-preprocess --encode` fills a cache ahead of time. For fragments cut out of larger proteins (e.g. a peptide-tiling library), `--embedding-context <FASTA file> --embedding-context-map <map>` embeds each fragment within its full-length protein rather than on its own, and `--embed-mean-subtraction` subtracts each embedding's mean over its residues before it is stored. See "Protein language model encodings" in the documentation.

For sequence-mapped data, `--encode nardini` gives every residue its sequence's 90 NARDINI+ features (36 patterning z-scores, each against scrambles of the sequence itself, and 54 compositional z-scores against the human IDRome), as computed by SPARROW (`pip install git+https://github.com/idptools/sparrow.git`; see Installation). Alone, with the `composition` baseline or the simple models, this is a model of the NARDINI+ features and the length; `--encode onehot+nardini` (or `biophysics+nardini`) puts them after each residue's own encoding, for the order-aware networks. The features are computed once, in parallel, into the embedding cache; `--nardini-scrambles` sets the number of scrambles (default 1,000). See the "NARDINI features" documentation page.

### Batching

By default (`--batching length`), training batches group sequences of similar length, re-randomised every epoch, so little computation is spent on padding; for datasets whose sequence lengths vary widely this makes training several-fold faster. Padding is masked, so it affects a network's output only through float32 rounding, and this only changes which sequences share a batch. `--batching random` restores the freely shuffled batches of earlier PARROT versions.

### Change log 

* PARROT2 (in development, on the `parrot2` branch): PARROT now requires Python 3.11 or newer, NumPy 2.3 or newer, PyTorch 2.8 or newer and h5py 3.10 or newer (for the embedding cache of protein language model and NARDINI+ encodings). Zero-padding is now masked during training (the LSTM only sees each sequence's real residues and padded residues no longer contribute to the loss), so predictions no longer depend on how sequences are batched (beyond float32 rounding); previously trained networks load and predict as before, up to float32 rounding. Fixed a crash when testing residue-classification networks with NumPy >= 1.24. The reported test loss now uses the same loss function as training/validation. `parrot-predict` writes one output line per input line (keeping every sequence ID) and skips blank/comment lines. Added a `--seed` flag to `parrot-train`, `parrot-optimize`, `parrot-cvsplit` and `parrot-preprocess`. Made a number of smaller input-validation and plotting fixes. Added an extensive test suite. Restructured PARROT so new network architectures can be added as a single module (see the "Adding a new architecture" documentation page): `parrot-train` and `parrot-optimize` take the architecture to train (as a subcommand; see below), and saved networks now record their architecture, hyperparameters, datatype, number of classes and encoding, so `parrot-predict` and `Predictor` no longer need these to be specified. Networks saved by earlier versions still load, and `BRNN_MtO`/`BRNN_MtM` are unchanged. Added four architectures alongside the BRNN: `cnn` (a dilated residual convolutional network), `unet` (a 1D U-Net adapted from the 2D U-Net on the parrot-lightning branch), `transformer` (a transformer encoder with rotary or sinusoidal positions) and `composition` (an order-independent baseline). By default the CNN and U-Net add a whole-sequence summary to every position, the BRNN, CNN, U-Net and transformer pool residues with learned attention (the BRNN previously used its final hidden states), and the BRNN, CNN, U-Net and transformer give their output layer log(sequence length) on sequence tasks; `--global-context-off`, `--attention-pooling-off` and `--loglength-feedforward-off` turn these off, and networks saved before these options existed load with them off. `parrot-optimize` now accepts architecture hyperparameter flags to fix those hyperparameters instead of searching them. `parrot-optimize` was rewritten without GPy/GPyOpt: it combines successive halving (configurations are dropped after a few epochs unless they are among the best) with model-based sampling (TPE), scores configurations on the validation set by default (`--cv-folds` for cross-validation), searches settings with fixed choices (e.g. kernel widths) as well as numbers, records every trial in `<output>_hyperparameter_trials.tsv`, and is about 15-20 times cheaper than before with its defaults; `--trials` replaces `--max-iter`, which still works. Added simple scikit-learn models for sequence-mapped data (`linear`, `svm`, `random_forest`, `knn`), fitted in one step to composition, length and optionally dipeptide-composition features. `parrot-preprocess` became a complete data-preparation tool: sequence cleaning (`--uppercase`, `--remove-nonstandard`, `--min-length`, `--max-length`), deduplication (`--deduplicate merge|first|drop`), splitting into training, validation and test sets with a matching split-file (`--split homology`, which uses MMseqs2 so that no set contains a homologue of another; `--split kmer`, the same protocol with PARROT's own k-mer search when MMseqs2 is not installed, which finds closer relatives only; or `--split random`; plus `--groups`), class balancing of the training set only, and a report of every step. Class balancing removes the fewest sequences needed for the best balance (sequence data), never makes the balance worse (residue data), and keeps the input order; `--cb-shuffle-off` no longer has any effect. Datafile errors now name the data line and say what is wrong with it. `parrot-preprocess --remove-line-duplicates` keeps every line in its original order (it used to regroup lines that share an ID). `parrot-cvsplit` makes its folds with the same code as `parrot-train`, so a given `--seed` gives different (equally valid) split-files than before. A `--datatype`, `--mode` or `--stop` value that is not one of the allowed choices now stops with a usage message. Figures are drawn with matplotlib alone in a plain style (Arial text that stays editable in vector editors, solid lines, no titles or grid lines), so pandas and seaborn are no longer needed. The unused `decode()`, `rev_one_hot()` and `rev_biophysics()` functions have been removed, and the `parrot` package now exports only its public names. Added matrix data: a matrix of values per sequence with one row per residue, either a square map of every pair of residues (optionally `--symmetric`) or `--matrix-width N` related values per residue, read from a NumPy `.npz` file (`--matrix-file`) with missing cells as NaN, for regression or classification. Matrix data is learnt by the new `unet2d` architecture, a 2D U-Net after the one written by Nick on the parrot-lightning branch. Predicted matrices are written as `.npz` files by `parrot-train`, `parrot-optimize` and `parrot-predict`, with heatmaps of example test sequences in the figures; `parrot-preprocess` cleans, deduplicates and splits matrix datafiles; and `--max-matrix-length` (default 512) refuses sequences whose square maps would not fit in memory. `parrot-train` and `parrot-optimize` now take the architecture as a subcommand (`parrot-train cnn --input-file data.tsv --output-network network.pt --split kmer -d residues --regression`), and each subcommand offers only the options that apply to that architecture: its own hyperparameters, the training options only for networks trained epoch by epoch, the matrix options only for `unet2d`, and `-d` only where there is a choice of datatype. They name every input, with no positional arguments: `--input-file` and `--output-network` (`.pt` is added if the name does not end with it); `--regression`, or `--classification` with `--num-classes N`, replace `-c`; and `--device cpu` replaces `--force-cpu`. Commands in the earlier form stop with a message saying what to use instead. Every network gets a `<network>_info.txt` describing how it was trained (the exact command and software versions, the data with its checksum, the split, the encoding, the architecture with its number of parameters, the loss, optimizer and epochs, the search for `parrot-optimize`, and the results), in enough detail for a paper's methods section. `--split` is now required, and is either a split-file or one of `parrot-preprocess`'s splitting methods: `mmseqs` or `kmer`, which keep similar sequences in the same set (found by MMseqs2, or by PARROT's own k-mer search) so that no test sequence has a close relative in the training set, or `random`. The methods aim for `--set-fractions`, and a file with the name given is always read first (so a split-file called `random` is still read as a file). `--split random` is closest to the old default, but now keeps identical sequences in the same set. With `--include-figs`, regression networks now get a density plot of predicted against true test values as well as the scatterplot, both labelled with Pearson's r; a scatterplot of more than 10,000 values shows 10,000 spread evenly over the test set, with a warning, as more would merge into a solid block, and residue networks get `_res_profiles.png`, the true and predicted values along six test sequences spanning the range of accuracy, each labelled with its Pearson's r and mean absolute error (or, for classification, its accuracy). `_info.txt` now also records how long training took, the time per epoch, the training speed and the prediction speed (sequences per second). `--probabilistic-classification` now also works for residue classification: each residue's class probabilities are written as one comma-separated token (e.g. `0.9100,0.0600,0.0300`), so tokens still line up with residues, and the ROC and precision-recall curves and their areas pool every labelled residue. Added NARDINI+ sequence features as an encoding for sequence-mapped data (`--encode nardini`, or `onehot+nardini` to follow each residue's own encoding), computed by SPARROW once per sequence, in parallel, into the embedding cache, with the settings saved with the network so new sequences are encoded identically. The commands report mistakes in their input as a one-line message rather than a traceback (`PARROT_TRACEBACK=1` shows the traceback too), start with a line giving PARROT's version, and say more about what they do: `parrot-train` and `parrot-optimize` report how the data were split, number epochs from 1 (always showing the last), say which epoch's network was kept, and end with the test-set metrics and the files written; `parrot-predict` prints its settings only with the new `--verbose`. Error messages name the file or option at fault and how to fix it (e.g. `--num-classes` for out-of-range class labels), and the help of every command was revised for accuracy and consistency. Every command now starts with a header giving PARROT's version and the time, and has a `--show-examples` option that prints a guide to the command: what it does, worked examples, and how it works. `--split kmer` now scores a run of shared k-mers by the residues they cover, and its E-values are calibrated on random sequences (they had been up to tens of times too significant, because the overlapping k-mers of one shared stretch counted as independent matches), so a single short shared word no longer links unrelated sequences or is reported as near-identical; it links slightly fewer distant relatives (in the yeast proteome, 76% of the pairs MMseqs2 links at 40-50% identity rather than 82%). With `--homology-evalue` above 0.01, the separation check now searches at that E-value, so it finds every pair that meets the criterion. MMseqs2 coverage now counts the shorter sequence's residues between the alignment's ends rather than alignment columns (which included gaps); MMseqs2 always reads the sequences as proteins; similar pairs are counted once in the report; and the separation check no longer removes training records that are similar only to a validation record that is itself removed. `parrot-preprocess` keeps a `--groups` link when deduplication removes one of a group's records, treats class labels that are the same number (`1` and `1.0`) as one class when merging duplicates, removes residue sequences that merging leaves with no label, stops with a message when cleaning or deduplication leaves no lines, ignores spaces around `--delimiter` fields and refuses fields containing whitespace (which its whitespace-separated output could not hold), and reads datafiles that start with a byte-order mark. `parrot-optimize --cv-folds` makes its folds as `--split` makes the sets: identical sequences are always in the same fold, and with `--split kmer` or `mmseqs` so are clusters of similar sequences, each fold being scored only on held-out sequences that are not similar to its training sequences (the folds used to be drawn at random, so held-out sequences could be copies of training ones); `parrot-cvsplit` also keeps identical sequences in the same set. The search's first stage is now exactly `--min-epochs` (by default a ninth of `--epochs`), giving three stages for any `--epochs` from 9 up (e.g. 6, 17 and 50 for `-e 50`, which used to get two); a search in which every configuration diverges stops with an error rather than saving a diverged network; models fitted in one step report their validation loss in `_info.txt`; hyperparameters that have no effect on the data are not searched (e.g. the composition window for sequence data, or dipeptide features with protein language model embeddings), nor are configurations that differ only in a setting the rest of the configuration ignores; and the `unet2d` search no longer reaches networks of over a billion parameters (at most about 41 million). Hyperparameters must be finite numbers (`inf` and `True` are refused), and `--dropout` must be below 1. Length batching (the default `--batching length`) now jitters each length before sorting, by a few percent when the training set is small enough to be sorted as one pool (most PARROT datasets) and less the more pools it fills, so the same sequences no longer share a batch every epoch; with a given `--seed`, training therefore gives slightly different results than before (the training snapshots were updated). Split-files must have exactly three lines (blank lines after them aside): a fourth line or a blank first line is now an error rather than being misread, and a value that is not a line number is reported with the file and line. Encoding files must give each residue as a single character followed by at least one value, and may start with a byte-order mark; a `.npy` file given as `--matrix-file` and matrices of complex numbers are refused with a message; `--exclude-seq-id` error messages count the file's own columns; and `split_data()`, `split_data_cv()` and `vector_split()` check their fractions and number of folds before reading any data. The test set is now predicted in batches of `--batch` (it was always 32, so a network that only fitted in memory at a smaller batch could fail after it was saved), and `parrot-predict` has a `--batch` option (default 64). A test set with fewer than two labelled values, a constant prediction or a diverged network now gives NaN correlations rather than a crash after the network is saved; class probabilities that are not finite give NaN curve areas and no ROC or precision-recall figures, with a warning; and for two classes the area under the ROC curve in the statistics is now class 1's, the one the ROC figure shows (it was the micro-average over both classes). `--stop auto` now stops once `-e` epochs in a row have not lowered the validation loss by at least 0.5% (relative to the last epoch that did): it stopped one epoch later than documented, and any new best, however small, restarted the count, so a slow steady decline never stopped it. Running in full float32 precision on NVIDIA GPUs uses PyTorch's newer `fp32_precision` settings where they exist (PyTorch 2.9 and later raises if a process mixes them with the older `allow_tf32` flags, and lowering the matmul precision with `torch.set_float32_matmul_precision` broke PARROT's). Several runs can now share one `--embedding-cache`: a run reading the cache no longer stops another adding to it (HDF5's file lock gave a raw locking error), and a run that wants to write waits for one that is writing; NARDINI features are cached per SPARROW version, so features from an older SPARROW are not reused after an upgrade. The whole-sequence summary of the CNN and U-Net (`--global-context-off` to turn it off) no longer draws random numbers when it is created, so a network built with it from a given seed now starts with the same other weights as one built without it, as documented (the architecture snapshots were updated). The transformer's `--head-size` must be at least 2 (with 1, rotary positions did nothing). `parrot-cvsplit` keeps every dot of its output prefix (`cv/splits_t0.8` and `cv/splits_t0.9` used to write the same files). `parrot-predict` checks `--print-frequency`, prints nothing with `--silent` even with `--verbose`, refuses a file that is not a PARROT network with a message, and checks matrix networks' sequence IDs before predicting; `Predictor` accepts `dtype='matrix'`. `--output-network` naming a directory, `--embedding-cache` with an encoding that has no cache, and out-of-range `parrot-preprocess` class-balancing options are now refused before any data are split or networks trained, and the few-batches warning fires below 10 batches per epoch, as documented. `parrot-cvsplit` takes `--exclude-seq-id` for datafiles without sequence IDs (it took their first value for the sequence, so identical sequences could be split between sets), and stops with a message if a line's sequence is a number. `parrot-train` notes a hyperparameter given that it knows has no effect on the network (e.g. `--window-radius` for sequence data), and `_info.txt` marks it as having no effect; not every such case is caught yet (the pooling options and `--loglength-feedforward-off` do nothing for residue data, but are not noted). With `--deduplicate merge`, copies of a classified sequence whose label is missing (`nan`) no longer count as disagreeing with the others. `parrot-optimize` no longer stops with "Every configuration failed" when the configuration it promoted fails at a later stage (e.g. by running out of GPU memory) while others trained fine: it trains the best of those again instead; and for the simple models, `_info.txt` no longer calls the search successive halving. `--split kmer` no longer understates the chance of a run that covers all of a short sequence (by the chance that a run continues, about 1% for typical compositions). Split-files holding values that only look like line numbers (such as `--2` or `1_0`) are refused with the file and line, rather than crashing or being misread; `parrot-preprocess` checks `--threads`, says so when `--class-balance` finds every label missing, and no longer crashes on an infinite class label; and a matrix file holding arrays of Python objects is refused with a message. Added `--uncertainties` to `parrot-train`, `parrot-optimize` and `parrot-preprocess`, for regression values that come with the standard deviation of their measurement error, written as `value,SD`: training minimises the Gaussian negative log-likelihood with variance SD² + s², where the model error s is refitted by maximum likelihood to the validation residuals after every epoch (the simple models are refitted with weights until it settles; `knn` cannot weight its training sequences); `--stop auto` then asks for a fall of about 0.005 per labelled value; the test statistics add the reduced chi-squared, the fraction of values within 1 and 2 total SDs, the noise ceiling and s; and `parrot-preprocess --deduplicate merge` combines copies by their inverse-variance weighted mean. The BRNN now takes `--dropout` too (off by default), applied to the LSTM output and between stacked LSTM layers, so every network trained by gradient descent has it; `parrot-optimize` does not search it, so BRNN searches try the same configurations as before. `parrot-preprocess --encode` computes a protein language model or NARDINI encoding of every sequence of its output ahead of time, into the embedding cache that `parrot-train`, `parrot-optimize` and `parrot-predict` read with `--embedding-cache`, so the encoding can be computed once and any number of networks trained on it. Embedding and computing NARDINI+ features now show a tqdm progress bar (redrawn every 30 seconds when the output goes to a file, such as a `nohup` log), so PARROT now requires `tqdm`. `--embedding-context` and `--embedding-context-map` (in `parrot-preprocess`, `parrot-train`, `parrot-optimize` and `parrot-predict`) embed each sequence within the full-length protein it was cut from, given a FASTA file of the proteins and a map from each sequence ID to its protein. `--embed-mean-subtraction` (in `parrot-preprocess`, `parrot-train` and `parrot-optimize`, and recorded in the network for `parrot-predict`) subtracts each embedding's mean over its residues (in context, the full-length protein's) before it is stored. The fragments' embeddings are cut out of the proteins' embeddings and cached in their own file, a table of where each sequence was embedded is written next to the output, and a network trained this way records it, so that `parrot-predict` and `Predictor` embed new sequences in the same way (or on their own, with `--embed-in-isolation`). `Predictor.predict_batch()` predicts a list of sequences at once, as `parrot-predict` does: it encodes them all first (protein language model embeddings in batches, NARDINI+ features on several cores, into `embedding_cache` or else a temporary cache deleted afterwards), then runs the network over batches of similar length, which is much faster than `predict()` on each sequence and gives the same predictions up to rounding (float32 rounding in the network, and for protein language model embeddings, which are also computed in batches, a stored 16-bit value can move by one step). `Predictor` now runs on a GPU if there is one (`device='auto'`, as for the commands; PARROT 1's ran on the CPU, which `device='cpu'` still chooses), and takes `gpu_id`, to choose which NVIDIA GPU it runs on, as `parrot-predict`'s `--gpu-id` does. Added `gbrt`, gradient-boosted regression trees (scikit-learn's histogram-based implementation), as a further simple model for sequence-mapped data: it takes the same features as the other simple models, supports `--uncertainties` and `--probabilistic-classification`, and `parrot-optimize` searches its number of trees, shrinkage, number of leaves, minimum leaf size, L2 penalty and fraction of features considered per split. PARROT now requires scikit-learn 1.4 or newer.
